Parallax a measuring instrument for Stellar projects

Usage, measured from two sides.

Astronomers cannot travel to a star to measure how far it is. They sight it twice, from opposite sides of Earth's orbit, and read the distance from how much it appears to move. That shift is called parallax.

A project's real usage is just as hard to reach. Today each team reports its own numbers, and nobody else can take the reading. Parallax sights it from two sides, the website and the API, with an instrument the project does not control.

See the live readings Test it yourself

Working prototype. Everything described here is running on this server now. It is not yet a production service.

A number nobody else can check

The Stellar Community Fund decides who to fund partly on how much a project is used. Those figures arrive written by the teams asking for the money. Each one counts in its own way, and a counter can be fed by a script as easily as by a person.

SCF asked for one shared instrument instead: the same for every project, free, private by design, and hard to inflate. This is our answer.

Forge a visit

The site's id is public, as it is in any analytics tool. Use it to add a visit from a terminal:

curl -s -X POST {{INGEST}}/e \
  -H 'Origin: {{DEMO_ORIGIN}}' \
  -d '{"type":"event","payload":{"website":"{{DEMO_WEBSITE}}","url":"/"}}'
{"code":"missing-token", ...}

The attempt is refused, and it appears in the readings as turned away, with the reason.

It will be counted, without the address

Call an API with a Stellar account

The demonstration API reports to Parallax through OpenTelemetry. Call it with any account:

curl -s {{API_DEMO}}/accounts/GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN/payments

About fifteen seconds later the readings list one more request to the route below. The account was never written down, and neither was the trace.

GET /accounts/{account}/payments

What the instrument refuses to keep

  • Full IP addresses. They are cut short inside the gateway, before anything else sees them. Only the country survives.
  • Cookies, or any identifier that would follow a visitor from one project to another.
  • Traces, spans and logs. The collector takes the counts and the timings, then throws the rest away.
  • Accounts, contracts and transaction hashes in API paths. They are replaced before storage.
GET /accounts/GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN/payments
GET /accounts/{account}/payments

Field notes, first evening online

  1. 20:51 UTC

    The instrument goes online on the smallest server money can rent: one processor core, two gigabytes of memory, in Helsinki.

  2. 20:53

    Two minutes later, strangers are already asking the demonstration API for /.env, /wp-config.php and /backup.sql. Each request became a new route in the readings. Anyone could have inflated a project's route list this way.

  3. 20:55

    Fixed. Requests for paths an API does not have now fall into a single entry. A problem that only real traffic could have shown us.

  4. by 21:12

    A visitor from the Netherlands, on Linux, reads this page. We do not know who. The prototype counts the visit as confident; the funded version would also weigh the network it came from.

  5. 21:29

    Load test. Two hundred API requests a second for five minutes: 60,000 sent, 60,000 stored, none lost, in five routes. That pace is seventeen times what SCF asked for, and no service used more than a twentieth of the core.

16 November 2026. Times are when we observed each thing, to the nearest few minutes.
